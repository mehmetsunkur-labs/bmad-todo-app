## Intent

**Problem:** The repository holds only planning artifacts. Every later story needs a running monorepo, a dev stack started by one command, the shared contract package, API conventions (errors, logging, config, shutdown), and the branded page frame.

**Approach:** Build the pnpm workspace (`apps/web`, `apps/api`, `packages/shared`, `e2e/`) at the pinned Stack versions. `docker compose up` starts `web` (Vite HMR), `api` (`tsx watch` with the inspector), and `db` (postgres:18). The API serves `GET /api/v1/health` through the AD-5 error handler and the AD-11 logger. The web shows an empty, branded "Todos" frame.

## Boundaries & Constraints

**Always:**
- Stack versions come from the architecture spine's Stack table (pnpm 12.6.0 via Corepack `packageManager`, Node 24).
- The only import directions are web → shared and api → shared. `packages/shared` depends only on `zod` and is consumed as TypeScript source (`"@todos/shared": "workspace:*"`).
- Every non-2xx response comes from the single `setErrorHandler` or `setNotFoundHandler` in `apps/api/src/errors.ts`, using the envelope `{error:{code,message,details?}}`.
- Config is `DATABASE_URL`, `PORT` (3000), and `LOG_LEVEL` (info), Zod-validated. Invalid values log an error and make the process exit with a non-zero code.
- Each request produces exactly one pino JSON line with `reqId`, `method`, `route`, `statusCode`, and `responseTime`. Bodies are never logged.
- The volume `todos-data` is mounted at `/var/lib/postgresql`. `PGDATA` is never set.
- Browser calls use relative `/api/v1` paths through the Vite proxy with no path rewrite. CORS stays off.

**Never:**
- In this story, no `todos` table or migration and no Todo schemas or endpoints (those arrive in 1.2 and 1.3).
- No nginx or production Dockerfile stages, and no `test:e2e` or `api:docs` implementation (Epic 3).
- No shadcn `--monorepo` layout and no `packages/ui`.
- No Todo UI, no Add row, and no toasts rendered.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Healthy | `GET /api/v1/health`, and `SELECT 1` succeeds | `200 {"status":"ok"}` | N/A |
| DB down | `GET /api/v1/health`, and the DB is unreachable | `503 {"error":{"code":"UNAVAILABLE","message":…}}` | The route throws `AppError('UNAVAILABLE')`. The server keeps serving |
| Unknown route | `GET /api/v1/nope` | `404 {"error":{"code":"NOT_FOUND","message":…}}` | Produced by `setNotFoundHandler` |
| Unexpected throw | A handler throws a plain `Error` | `500 INTERNAL` envelope with no stack in the body. Logged at `error` level with the stack | The next request still succeeds |
| Bad config | `PORT=abc` or `DATABASE_URL` missing | The process exits with a non-zero code before listening | A clear error log names the variable |
| SIGTERM | The running API receives SIGTERM | `fastify.close()` runs, then `pool.end()`, then the process exits with code 0 | N/A |

## Design Notes

`compose.yaml` is shared as the base in 1.1, but it isn't runnable on its own until Story 3.1 adds the production Dockerfile stages and nginx. The Dockerfiles in this story only have a `dev` stage, which `compose.override.yaml` selects with `build.target: dev`. The dev `web` service maps `${WEB_PORT:-8080}` to Vite's port, so the URL is the same in both modes.
