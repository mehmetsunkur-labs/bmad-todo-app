## Intent

**Problem:** The page shows only the "Todos" frame, and there is no `todos` table, list endpoint, or client data layer. The user can't see their Todos, and a failed load isn't distinguishable from an empty list.

**Approach:** Add the first migration (the `todos` table) and `GET /api/v1/todos` (route → service → repository, ordered by `compareTodos`). On the web, add the AD-6 data layer (`http.ts`, pinned `query-client.ts`, `todo-sync.ts` confirmed-state seeding, `useTodosQuery`) and render exactly one List State: Loading (skeleton after 300 ms), Empty, Load error with "Try again", or Populated rows showing the Description and Created At.

## Boundaries & Constraints

**Always:**
- Shared owns `TodoSchema`, `TodoListResponseSchema`, `compareTodos`, and `TODOS_PATH`.
  - Response schemas strip unknown keys (`z.object`), because AD-2 says clients ignore unknown response fields.
  - Request schemas remain `.strict()` (AD-1).
  - Change `HealthResponseSchema` to strip unknown keys too.
- The table columns are `id uuid pk`, `description text not null`, `completed boolean not null default false`, and `created_at`/`updated_at timestamptz(3) not null default now()`.
  - The migration is generated by drizzle-kit and committed under `apps/api/drizzle/`, then applied at startup before listening.
- The repository is the only code that uses Drizzle. It takes `ctx` first, orders by `created_at desc, id desc`, and maps `Date` → ISO string with millisecond precision.
- On the web, `http.ts` is the only `fetch` caller. It uses a relative path and `AbortSignal.timeout(REQUEST_TIMEOUT_MS)`, and parses responses with the shared schemas. Failures are classified by kind:
  - a fetch rejection or timeout is `NETWORK`;
  - a response body that isn't the envelope is `INTERNAL`;
  - otherwise the envelope's `code` is used.
- The QueryClient uses the pinned AD-6 defaults. "Try again" calls `resetQueries({ queryKey: ['todos'] })`. Nothing calls `invalidateQueries`.
- Descriptions render as React text only, with `overflow-wrap: anywhere`, no truncation, and no linkification. The list is `<ul aria-label="Todos">` inside `<main>`.
- Copy is exact:
  - Empty state: "Nothing here yet." / "Add your first todo above."
  - Load error state: "Couldn't load your todos." / "Check your connection and try again." with a secondary "Try again" button.

**Never:**
- No Add row, input, checkbox, row actions, toasts, `createTodoMutation`, or write endpoints (Stories 1.3, 1.4, and Epic 2).
- No `dangerouslySetInnerHTML`, no browser storage, no refetch on focus or mount, and never show an empty list when the load failed.

**Decisions:**
- **Created At format:** a `<time dateTime={iso}>` element in `en-US`.
  - Under 1 minute: "just now". Under 60 minutes: "{n}m ago". Same calendar day: "{n}h ago". Previous calendar day: "yesterday". Otherwise "MMM D", with ", YYYY" added when the year differs.
  - A pointer-hover shadcn `Tooltip` shows the full date and time, e.g. "Sep 24, 2026, 9:14 AM".
  - While the row has `:focus-within`, it shows "Created {full}" and adds no tab stop.
  - A single shared minute ticker drives the refresh, so each time element re-renders without re-rendering the list.
- **Focus after "Try again"** (human decision, review loop 1): pressing "Try again" moves keyboard focus to the list region, a `tabIndex={-1}` container that wraps whichever List State is shown (skeleton, Empty, rows, or the error again). Focus stays on that container as the state resolves, so it is never lost to `<body>`, and the container adds no tab stop.
- **Row layout:** until Epic 2 adds the checkbox and actions, the row is a single column (Description, then the time on the line below). It has the 12 px vertical padding, a minimum height of 44 px, and a 1 px bottom border. It is transparent, with no hover background, and the row itself is not clickable. The time uses the `meta` style in `muted-foreground`.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| List ordering | 3 rows, two with the same `created_at` | `200 {"todos":[…]}` ordered by `createdAt` desc, then `id` desc, with ms ISO strings | N/A |
| Empty DB | No rows | `200 {"todos":[]}` → the Empty state with its exact copy | N/A |
| Fast load | Data arrives in under 300 ms | No skeleton ever renders | N/A |
| Slow load | Data arrives after 300 ms | 4 `aria-hidden` skeleton rows, and the `<ul>` has `aria-busy="true"` until the data arrives | N/A |
| Load failure | Network error, 5xx, a non-envelope body, or a 10 s timeout | The Load error state with `role="alert"`, never an empty list | "Try again" → Loading → the refetched result, with focus on the list region, never `<body>` |
| Unsafe text | Description `<b>x</b> https://a.b` or 500 unbroken characters | Shown literally, not linked, and wrapped with no horizontal scroll at 320 px | N/A |
| Extra field | The response Todo has an unknown key | Parsed successfully; the key is ignored | N/A |
