### F1: The documented dev-stack refresh leaves stale `node_modules`, so the dev API crashes after Story 3.2 (3.2 ↔ 3.1/1.1) · **fix now**
- **Evidence:**
  - README.md:53, :56 and :147 prescribe `docker compose up --build -V` after a dependency change and say "`-V` only renews anonymous volumes".
  - The six `*-node-modules` mounts in `compose.override.yaml` are named volumes, declared under the top-level `volumes:`, so `-V` never renews them.
  - 3.2 added the runtime dependency `@fastify/swagger` (`apps/api/package.json`, imported by `apps/api/src/openapi.ts`).
  - The `todos_api-node-modules` volume on this host has no `@fastify/swagger` (verification-gap lens, read-only volume inspection).
  - The dev API crashed on exactly this import during 3.2 (`spec-3-2-…` Auto Run Result, "Dev API crash").
- **Why no test saw it:** nothing boots the dev stack. The only dev-mode test is a `docker compose config` parse (`scripts/stack-smoke.test.mjs` "dev config"), and the 3.2 walkthrough ran the prod path only (`docs/onboarding-walkthrough.md:5-18`).
- **Also wrong:** the session's own advice to the owner ("restart with `docker compose up --build -V`").
- **Prevention:** a dev-stack boot check, and README commands executed rather than only proofread.

### F2: Test harnesses rebuild the owner's real `todos-*:prod` images (3.1 ↔ 3.3/3.4) · **fix now**
- **Evidence:**
  - `compose.yaml` tags `todos-api:prod` and `todos-web:prod`.
  - `scripts/stack-smoke.test.mjs` (`up -d --build`) and `e2e/scripts/run-e2e.mjs` (`up -d --build --wait`) build the working tree into those same global tags. That includes uncommitted edits.
  - The README only says to "use `--build`". Recorded as a residual risk in the 3.1, 3.3 and 3.4 results, but routed nowhere.
- **Consequences:**
  - A later `docker compose -f compose.yaml up -d` without `--build` on the real stack runs test-built code. If that code carries a migration, the change to `todos-data` is irreversible (adversarial and edge-case lenses).
  - Concurrent runs can swap images under each other's durability and recreate tests.
- **Prevention:** per-harness image tags.

### F3: Two Docker harnesses solve the same problems independently, and they have drifted (3.1 vs 3.3/3.4) · **fix the small parts now, defer the consolidation**
- **Duplicated between** `scripts/stack-smoke.test.mjs` (525 lines) **and** `e2e/scripts/run-e2e.mjs` + `e2e/tests/fixtures.ts` + `durability.spec.ts`:

### F7: The OpenAPI document promises the error envelope for every non-2xx, but nginx sends HTML (3.1 ↔ 3.2) · **fix now (doc) / defer (nginx)**

- **What nginx does:**

- **Why it matters:** a client generated from the document mis-handles exactly the outage cases the document describes. The in-app client already treats non-envelope bodies as `INTERNAL`, so the app itself is fine.
